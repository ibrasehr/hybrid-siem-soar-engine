# hybrid-siem-soar-engine
Python-based next-gen SIEM/SOAR platform featuring hybrid ML correlation, UEBA insider threat detection, governed automated response with transactional rollback, and explainable AI traces.

## Correlation Engine & Offline Pipeline

The correlation module combines a Random Forest classifier with behavioral rule tracing, target leakage protection, threshold sweeping, drift testing, and schema-validated JSON alert generation.

### Installation

1. Create and activate a Python virtual environment:
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

2. Install dependencies:
```powershell
pip install -r requirements.txt
```

### Training & Running the Offline Evaluation Pipeline

Run the end-to-end evaluation benchmark (multi-seed threshold sweep, speed benchmark, and leave-one-family-out drift test):

```powershell
.\.venv\Scripts\python.exe correlation_pipeline.py --csv data/UNSW_NB15_training-set.csv --label-col attack_cat --benign Normal
```

With feature ablation (e.g., dropping synthetic testbed artifacts):
```powershell
.\.venv\Scripts\python.exe correlation_pipeline.py --csv data/UNSW_NB15_training-set.csv --label-col attack_cat --benign Normal --ablate sttl,ct_state_ttl,ct_dst_src_ltm
```

### Running the CorrelationEngine CLI

Train the `CorrelationEngine` and evaluate events to produce schema-validated JSON Lines alerts:

```powershell
.\.venv\Scripts\python.exe correlation_engine.py --train-csv data/UNSW_NB15_training-set.csv --input-csv data/UNSW_NB15_training-set.csv --threshold 0.5 --out alerts.jsonl
```

### Running Tests

Execute the automated test suite with pytest:
```powershell
.\.venv\Scripts\python.exe -m pytest -v tests/test_engine.py
```

### Output Files

- `results/threshold_results.csv`: Single-seed threshold sweep metrics (recall, FPR, precision) for both the rule baseline and Random Forest.
- `results/threshold_multiseed.csv`: Multi-seed threshold sweep metrics reporting mean and standard deviation across seeds.
- `results/drift_results.csv`: Leave-one-family-out evaluation metrics across unseen attack families.
- `results/speed_results.csv`: Inference throughput (events/sec) and latency across batch sizes (100, 1,000, 10,000).
- `results/ablation_*.csv`: Corresponding evaluation outputs when running with `--ablate`.
- `schema.json`: Formal JSON Schema defining the required structure for incident alerts.
- `sample_alert.json`: Representative schema-compliant incident alert record with feature importance tracing and fired behavioral rules.
- `alerts.jsonl`: Line-delimited JSON alerts generated by the `CorrelationEngine` CLI.

### Limitations

1. **Benchmark Split**: The evaluation is evaluated using stratified train/test splits on a single benchmark dataset (`UNSW_NB15_training-set.csv`). Real-world enterprise traffic may exhibit time-series dependencies and higher distribution shift.
2. **Speed Measurement Scope**: The speed benchmark measures model scoring and inference throughput in memory only (`predict_proba`). It does not measure end-to-end network packet capture, stream ingestion, feature computation, or disk persistence overhead.
3. **Rule Baseline Implementation**: The rule baseline consists of 5 hand-written domain-specific threshold rules fitted to the 99th percentile of benign training traffic, rather than a full stateful Wazuh SIEM engine or its complete production XML ruleset.
